# database-connection-pool-sizer

按延迟、排队和公平性约束计算数据库连接池容量。不使用平均值公式（如
Little's Law 直接拍脑袋），而是对每个候选池大小运行**确定性离散事件
模拟**，输出推荐配置和每个服务的预期风险。

## 快速开始

```bash
python -m unittest          # 运行全部测试（无需真实数据库）
python -m pool_sizer request.json   # 对 JSON 请求输出推荐配置
```

Python 3.8+，仅标准库。

## 输入

`PlanRequest`（或等价 JSON）：

- `services[]`：每个服务的到达率 `arrival_rate`、事务时长离散分布
  `durations`（`[(秒, 权重), ...]`）、最大等待时间 `max_wait`、调度权重
  `weight`、保留连接数 `reserved`（为长事务服务保留的最小容量）、峰值
  倍率 `peak_multiplier` 与峰值占比 `peak_fraction`；
- `instances[]`：主/从实例的路由权重 `weight` 与实例允许的最大连接数
  `max_connections`；
- `candidates`：多个候选总连接数；
- `tenant_concurrency`：各租户的预期并发上限；
- `timeout_budget`：可接受的单服务超时率（默认 1%）。

## 输出

`plan_pool` 返回：推荐总连接数、跨实例分配、整体可行性、每个候选的
评估明细，以及每个服务的风险（到达/完成/超时数、超时率、平均与 p95
排队时间、等待占 `max_wait` 比例、low/medium/high 风险等级）、各租户
平均/峰值连接占用和各实例利用率。候选超过实例上限之和时标记为
`exceeds_instance_limits`；全部候选不可行时仍推荐风险最小者并标记
`feasible=False`。

## 模拟假设

- **确定性**：到达时刻由强度函数（基础速率 + 峰值段倍率）的积分反函数
  解析生成；事务时长用黄金比例低差异序列在离散分布上取值；事件堆以
  `(时间, 类型, 单调序号)` 排序，耗时几乎相同的并发到达按固定规则打破
  平局。相同输入必然得到相同输出，不依赖随机数与真实数据库。
- **路由**：请求按实例权重以"加权最少已分配"轮询分配到主/从实例，
  各实例独立模拟；租户并发上限与保留连接按实例权重比例拆分。
- **连接分配**：总连接按实例权重以最大余数法分配，实例达到
  `max_connections` 后余量自动流向其他实例；放不下则候选不可行。
- **排队调度**：连接释放时先丢弃队首已超时请求；跳过达到租户并发上限
  的服务；保留连接专属于对应服务（服务占用低于保留数时优先，非保留
  占用总量不超过 `容量 - 保留总量`）；其余按加权公平排队
  （`已服务数/权重` 最小者优先），服务内部 FIFO。
- **超时**：请求等待超过 `max_wait` 即放弃并计入超时率；模拟结束时仍
  滞留队列的请求按超时计。
- 连接获取即事务开始，事务期间独占连接，释放立即可复用；模拟时长
  `horizon` 之外的到达不计入。

## 未覆盖的数据库内部开销

本工具只模拟连接池层面的排队与占用，**不**建模以下数据库内部行为：

- 查询执行计划变化、缓冲池/缓存命中率对事务时长的影响；
- 锁竞争、死锁、MVCC 版本清理（vacuum）与写放大；
- 连接建立/销毁的 TCP 与认证握手开销、连接空闲回收；
- 主从复制延迟及其对读一致性和从库负载的影响；
- 数据库自身的 `max_connections` 内部预留（超级用户保留连接）、
  后台 worker 占用；
- 网络抖动、TLS、连接池中间件（如 pgbouncer）的事务/会话复用模式。

事务时长分布应通过生产观测（慢查询日志、APM）标定，并预留余量吸收
上述未建模开销。
